# Черновик правки протокола (НЕ применён) — редакция C

Решение владельца 2026-11-15: сначала эксперимент, потом протокол.
Решение владельца 2026-11-15 (второе): **в правилах чисел нет** — цифру нельзя
подтвердить достаточно, поэтому правило не может на ней стоять.

## 0. Принцип, из которого всё выведено

> Правило формулируется предписанием. Число в правиле допустимо только как
> **соглашение** (порог, с которым агент сравнивает), и тогда оно помечено как
> решение, а не как результат замера. Число-доказательство живёт в дневнике или
> файле эксперимента и в правило не попадает.

Проверка: уберите из правила все числа — правило осталось исполняемым? Если нет,
оно написано через доказательство и подлежит переписыванию.

## 1. `~/.config/opencode/AGENTS.md` — §11.1 (после §11, до §12)

```markdown
## §11.1. Code Mode: сенсоры в коде, суждение в модели
- Нужно несколько последовательных вызовов по одному вопросу и харнесс умеет
  исполнять код с доступом к инструментам → собери их одним скриптом.
- В ответ возвращай поля, а не дампы: полный вывод — в файл, в контекст его путь.
- Промежуточный результат проверяй кодом, а не пересказом ответа инструмента.
- Скрипт, который может понадобиться снова, сохрани как артефакт и сошлись на
  него в task state.
- Композитный тул — вариант, а не обязанность: он даёт обзор, но не заменяет
  точный поиск места.
Guard: «проверено» подтверждается кодом возврата или хэшем артефакта; текст
  скрипта и пересказ его вывода доказательством не являются.
```

Чисел нет. «Несколько» — намеренно оценочная формулировка: порог здесь не измерен,
а выбирается по ситуации; выдавать ему числовой вид значит имитировать точность.

## 2. `skill templates` — поля без чисел

- task state: `Script: <path> | none | not-applicable:<причина>`.
- бриф суб-агенту: возврат = `script path` + `sha256` + дистиллят (поля, не дампы);
  полный вывод инструментов возвращать запрещено.
- эксперимент: ось «рука» = `sequential | composite | script`; метрика —
  `tokens_to_context` (как в `experiments/code_mode_2026_11`).

Числовых бюджетов (`≤512 токенов`, `≤3 вызовов`) здесь нет: они выглядели как
измеренные, а были моим произволом. Если проект хочет бюджет — он объявляет его
как своё соглашение, в своём `AGENTS.md`, с пометкой «решение».

## 4. Skill `code-mode` (`~/.config/opencode/agent_docs/code-mode.md`)

Триггер: «несколько однотипных вызовов», «fan-out по файлам», «агрегировать»,
«посчитать по многим ответам».

Содержание: (1) паттерны — map-reduce по файлам, поиск-и-фильтр, сравнение двух
деревьев, negative control внутри скрипта; (2) что делать, когда ответ не влезает:
файл + путь; (3) чек-лист «скрипт вместо проверки» — главный привал: агент
отчитывается своим же дистиллятом.

Таблиц замеров в скилле нет. Если агенту нужно число — он идёт в файл эксперимента
и читает его как данные, а не как норму.

## 5. Отклонённые редакции (и почему)

**A (числа в ядре) и B (числа как параметры).** Обе опирались на замер, у которого
честный статус — «один прогон, корпус обучен под поиск, контрольная рука зависит от
эвристики выбора символа, модели в цикле нет». Такой замер не подтверждает порог, а
число в ядре протухает при первой же переиндексации: в двух прогонах максимум
объёма ответа отличался на треть. Правило, которое ломается от смены индекса, — не
правило.

Числа остаются здесь, в отчётах, как история попытки:
`RESULTS.md` (v2), `results/v1_superseded/` (отменённая v1).

## 6. Что НЕ кладём в протокол

- Требование «всегда пиши скрипт»: для одного вызова скрипт дороже.
- Разрешение write-операций внутри скрипта: путь записи — `preview → impact_token
  → ack` (`docs/en/SECURITY.md:64-82`), он несовместим с fire-and-forget.
- Чужие числа (Cloudflare 1.2M→1k): не перевыведены.
- Любые числа как обоснование правила — см. §0.

## 7. Риск этой редакции, названный честно

Правило без чисел труднее проверить на соблюдение: «собери в скрипт» не имеет
числового порога, значит и нарушение не автоматизируется. Компенсация — Guard:
проверяется не «сколько», а «есть ли путь скрипта в task state» и «есть ли sha
артефакта». Это машинно проверяемо, в отличие от процентов экономии.
