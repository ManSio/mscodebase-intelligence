# HYPOTHESES — Code Mode: цена механизма при равном качестве

Заморожено ДО прогона: 2026-11-15. После первого взгляда на результат этот файл
не правится.

## Вопрос эксперимента

При **одинаковых данных** три способа доставить агенту ответ стоят по-разному в
контексте. Насколько дешевле «код, который проецирует результат» (arm C), и
теряет ли он факты по сравнению с полным дампом (arm A)? И не теряет ли факты
композитный тул `investigate` (arm B) — то есть можно ли заменить Code Mode
композитным тулом?

## Руки

| Рука | Механизм | Что возвращает |
|---|---|---|
| **A** (control) | 3 последовательных `tools/call`: `search_code` → `get_symbol_info` → `impact_analysis` | полные ответы, как их получает клиент (JSON-RPC) |
| **C** (treatment) | те же 3 вызова **внутри одного скрипта**, затем код-проекция | только строки с путями/счётчиками/риском |
| **B** (альтернатива) | один композитный `investigate(query)` | сфузированный markdown |

A и C видят **один и тот же сырой ответ** — сравниваются только проекции. Это и
есть внутренний контроль: проекция обязана не терять gold.

## Гипотезы (с фальсификаторами)

| # | Гипотеза | Фальсификатор |
|---|---|---|
| H1 | Проекция C не теряет gold там, где он есть в A: `hit_C ⊇ hit_A` в ≥95% кейсов | хотя бы в 3 из 48 кейсов gold есть в A и нет в C |
| H2 | Медиана `tokens_C / tokens_A` ≤ 0.20 | медиана > 0.30 |
| H3 (ожидаю провал) | `investigate` (B) теряет точный путь в ≥20% кейсов, где A его нашёл — значит композит не заменяет Code Mode для задач «где именно» | потеря < 5% кейсов |
| H4 | Проекция укладывается в бюджет: `tokens_C ≤ 800` в каждом кейсе, т.е. протокол может назвать число | хотя бы в 5 кейсах > 1000 |

H3 намеренно ожидается к провалу: если композитный тул не хуже, то §11.1 должен
толкать `investigate`, а не скрипты.

## Рубрика (машинная, да/нет)

- `hit` — путь `gold_file` присутствует в тексте, который вернула рука
  (нормализация `\` ↔ `/`). Скорер проверен на подделанном gold (обязан дать miss).
- `tokens` — cl100k_base по тексту, который клиент кладёт в контекст модели.
- `ms` — wall clock вызовов, без старта сервера.
