# Code Mode в протоколе: что это, что у нас уже есть, как встроить

Дата: 2026-11-15. Статус: 🔭 исследование + 🧪 замеры, **кода в репозитории не менял**
(встраивание = L, решение владельца). Реестры (`EXPERIMENTS_LOG.md`) не трогал —
это чужая территория в этой сессии, предложение ниже.

## 0. Вопрос и критерий ответа

Вопрос владельца: как встроить подход «Code Mode» (видео + блог Cloudflare) в
глобальный протокол, в «Машину» и шаблоны, чтобы это работало во всех проектах,
включая новые.

Критерий ответа: (1) отделить в Code Mode то, что даёт экономию, от того, что даёт
риск; (2) для каждой части указать, где она живёт — харнесс / сервер / протокол /
шаблон; (3) каждое число — из замера этого репозитория, с командой перевывода;
(4) варианты с ценой и откатом.

## 1. Что утверждает первоисточник (и что не подтверждено)

[источник: Cloudflare Blog, «Code Mode: the better way to use MCP»,
https://blog.cloudflare.com/code-mode/, опубликовано 2025-09-26, проверено 2026-11-15]

Подтверждено текстом блога:
- MCP-тулы конвертируются в TypeScript-API (интерфейсы + doc-комментарии из схемы);
- агенту показывается **один** инструмент — «выполнить код»;
- код исполняется в изоляте без доступа в интернет; единственный выход наружу —
  bindings, представляющие подключённые MCP-серверы; ключи живут в супервизоре,
  не в песочнице;
- возврат результата агенту — через `console.log()`.

**Не подтверждено:** цифра «1 200 000 → 1 000 токенов / 2500 API» из видео. В блоге
её нет; наш собственный дневник цитирует другую пару — 150k→2k (−98.7%)
(`AGENT_DIARY.md:1784`). Это числа чужого замера, у нас они не перевыведены.

Ключевая мысль блога, которую легко потерять: экономия не в «песочнице», а в том,
что **цикл вызовов происходит вне нейросети** — модель пишет код, код дёргает API,
в контекст возвращается только выжатый результат.

## 2. Что у нас уже есть (проверено в этой сессии)

| Факт | Подтверждение |
|---|---|
| MCP-сервер отдаёт 17 тулов в профиле `core`, 70 в `full` (69 + `execute_script`, у владельца включён) | `tools/list` по реальному протоколу: `raw/tools_core.json`, `raw/tools_full.json` |
| Code Mode **уже работает** в этом харнессе: все 17 core-тулов вызываются из одного JS-скрипта, в контекст попадает только то, что скрипт вернул | `execute` → `tools["mscodebase-intelligence"].*`, 17 записей в каталоге |
| `execute_script` в MSCodeBase — **не** Code Mode: импорт ограничен allowlist stdlib, `import src.*` блокируется AST-валидатором | `src/core/sandbox/executor.py:36-54` (ALLOWED_MODULES), `:246-262` (импорт-гейт), `src/mcp/tools/codebase_tool.py:400` |
| Вызов тула без MCP-протокола уже реализован: DI + `cls(services).execute(**args)` | `src/cli.py:108-121`; allowlist — 7 тулов (`:28-45`) |
| Композитный тул «один вопрос → один ответ» существует | `investigate` (search+symbols+grep, затем impact/callers/tests) |

Вывод: харнесс-половина Code Mode у нас есть (OpenCode). Серверная половина —
нет: MSCodeBase не умеет «код, который вызывает свои же тулы».

## 3. Замеры (cl100k_base как BPE-прокси, метод в `scripts/measure2.py`)

### 3.1 Стоимость витрины инструментов (то, что клиент кладёт в контекст модели)

| Профиль | JSON-схемы | только сигнатуры | сигнатуры + doc из описаний |
|---|---:|---:|---:|
| core, 17 тулов | 4 597 tok | 524 tok | **1 437 tok** |
| full, 70 тулов | 14 766 tok | 1 576 tok | **5 053 tok** |

- `sheet+doc` — честная оценка: `.d.ts`-формат Cloudflare переносит описание, но
  убирает JSON-плумбинг. Экономия **−69%** (core) и **−66%** (full).
- «Только сигнатуры» (−89%) — нечестная планка: без описаний модель угадывает
  семантику параметров. В отчёт её кладу как границу диапазона, не как цель.

Перевывод:
```
python experiments/code_mode_2026_11/scripts/probe_tools.py core  raw/tools_core.json
python experiments/code_mode_2026_11/scripts/probe_tools.py full  raw/tools_full.json
python experiments/code_mode_2026_11/scripts/measure2.py
```

### 3.2 Цена ответа на один и тот же вопрос тремя способами

Полный замер — `RESULTS.md` **v2** (n=48 замороженных запросов). Короткая версия,
парно на кейсах, где baseline попал (n=34):

| Рука | Попаданий в gold | Токенов (медиана) | мс (медиана) |
|---|---:|---:|---:|
| A. цепочка 1–3 вызова, полные дампы | 34/34 | 2 323 | 224 |
| C. те же данные, проекция кодом | 34/34 | **389 (−82%)** | не измерено (те же вызовы) |
| B. один композитный `investigate` | 28/34 | 656 | **3 855 (17×)** |

**Внимание: числа v1 отменены.** В v1 руке A подсказывали имя gold-файла, из-за
чего A «выигрывал» 85.4% против 62.5% у композита. После удаления утечки разница
по попаданию в gold статистически не показана (McNemar exact p = 0.289, 6:2 на 8
несовпадающих), а выигрыш проекции остался: −82% токенов при тождественном
попадании. Подробности — `RESULTS.md` §0.

### 3.3 Чего в этих числах нет

- **Ходы модели.** A = 3 модельных шага, B = 1, C = 1. Ходы не измерены (нет сети
  и бюджета); по нашему же корпусу 1.37% ошибок на вызов → 25.1% сессий с ошибкой
  (`PIPELINE_DESIGN.md` C3). Это довод, но не замер этой сессии.
- **Качество ответа.** Ни одна из трёх рук не проверена на gold-ответах.

## 4. Что из этого следует: Code Mode состоит из четырёх независимых слоёв

| Слой | Что даёт | Где живёт | У нас сегодня |
|---|---|---|---|
| **L1. Витрина** — тулы как типизированный API вместо JSON-схем | −66…−69% входа | харнесс | OpenCode: да (компактный каталог); Zed: нет |
| **L2. Локальность цикла** — скрипт вместо N ходов | −81…−98% на цепочке, минус ходы | харнесс | OpenCode: да |
| **L3. Граница возможностей** — песочница с bindings, без сети и ключей | безопасность | **сервер** | нет: `execute_script` без доступа к тулам |
| **L4. Воспроизводимость** — скрипт = артефакт, рецепт перезапуска | проверяемость | протокол + шаблоны | частично: правило «рецепт, а не артефакт» |

Главный вывод: **L1 и L2 уже оплачены харнессом**. Вкладываться нужно в L3/L4 —
и только там, где харнесс не помогает (Zed, скрипты, CI, новые проекты).

## 5. Как это встроить

### 5.1 Глобальный протокол (ядро): редакция C — без чисел

Принцип (решение владельца 2026-11-15): число-доказательство в правило не попадает;
число в правиле допустимо только как соглашение и помечается как решение.

```markdown
## §11.1. Code Mode: сенсоры в коде, суждение в модели
- Нужно несколько последовательных вызовов по одному вопросу и харнесс умеет
  исполнять код с доступом к инструментам → собери их одним скриптом.
- В ответ возвращай поля, а не дампы: полный вывод — в файл, в контекст его путь.
- Промежуточный результат проверяй кодом, а не пересказом ответа инструмента.
- Скрипт, который может понадобиться снова, сохрани как артефакт и сошлись на
  него в task state.
- Композитный тул — вариант, а не обязанность: он даёт обзор, но не заменяет
  точный поиск места.
Guard: «проверено» подтверждается кодом возврата или хэшем артефакта; текст
  скрипта и пересказ его вывода доказательством не являются.
```

Аргументы и числа (замеры, p-значения, разброс между прогонами) остаются выше в
§3.2 и в `RESULTS.md` — как история попытки, а не как основание правила.

Почему в §11, а не в §2 «Машина»: «Машина» — про решение (Feed → Evidence Gate),
скрипт — про инструмент. Единственная связка нужна в шаге Feed: «сбор доказательств
одним скриптом» — одна строка, иначе протокол раздвоит цикл на два.

### 5.2 Шаблоны (skill `templates`)

- **task state**: поле `Script` (`path | none | not-applicable:<причина>`).
- **бриф суб-агенту**: возврат = `script path` + `sha256` + ≤512-токенный дистиллят,
  запрещено возвращать полный вывод тулов.
- **эксперимент**: ось «рука» = sequential | composite | script; метрика —
  `tokens_to_context` (как в §3), а не «на глаз».

### 5.3 Новые проекты

Протокол глобальный (`~/.config/opencode/AGENTS.md`) — наследуется всеми. Новому
проекту нужен только короткий блок в его `AGENTS.md`:

```markdown
## Code-mode capability
- harness: <opencode: execute с доступом к tool'ам | zed: прямой tools/call>
- composite tools: <investigate, get_context, ...>
- script dir: experiments/<task>/scripts/ ; в контекст — путь + sha256
```

Без этого блока агент в новом проекте не знает, есть ли L2, и по умолчанию
скатывается в цепочки по одному вызову — то, что мы и измеряли как руку A.

### 5.4 Серверная часть (MSCodeBase), если решим строить

`run(script)` — **только read-tools**, in-process, через существующий DI-диспетчер
(`src/cli.py:108-121` — тот же механизм, но allowlist шире 7):
`search_code, get_symbol_info, grep_code, graph_query, impact_analysis,
read_live_file, investigate, predict_change, get_context, codebase(status|git)`.

Почему read-only на первом шаге: выигрыш по токенам весь в цепочках чтения (§3.2),
а путь записи — это state-machine `preview → impact_token → ack`
(`docs/en/SECURITY.md:64-82`), которая несовместима с «скрипт отработал и забыл».
Запись внутри скрипта = L, отдельный ADR и матрица обхода.

## 6. Варианты

**v2-поправка после аудита:** замер не показывает, что композитный тул хуже цепочки
(p = 0.29) — показывает, что **выигрыш даёт проекция** (−82% токенов при
тождественном попадании). Поэтому B рекомендован не «вместо композита», а как
единственный способ дать проекцию там, где харнесс не умеет code-mode.

| | Что делаем | Цена | Плюс | Минус / риск |
|---|---|---|---|---|
| **A** | Только текст протокола + skill `code-mode` + поля в шаблонах | 1 сессия, дифф в 3 файлах | дёшево, обратимо, закрывает L4; работает уже сейчас в OpenCode | правило без механизма: в Zed/CI агент пишет «not-applicable», и правило мёртвое |
| **B (рекомендую)** | A + `run(script)` read-only в MSCodeBase | M (сервер, allowlist, лимиты, тесты) | механизм для хостов без code-mode; скрипт = артефакт с sha; переиспользует `cli.py` | +1 поверхность вызова; надо доказать, что AST-гейт не обходится (матрица) |
| **C** | B + запись внутри скрипта | L | максимум экономии | state-machine ack ломается, риск «12 файлов молча»; нужен ADR + red team до кода |

## 7. Red Team (атака → защита), до любого кода

1. **Злоупотребление: prompt-injection в индексированном файле** → скрипт вызывает
   write-тул. Защита: read-only allowlist в диспетчере, не в промпте; write-тулы
   недоступны из `run` (fail-closed).
2. **Границы: скрипт печатает 1 МБ** → контекст сгорает, «экономия» отрицательная.
   Защита: cap вывода (например 8 КБ), обрезка с маркером; превышение = ошибка, не
   тихий truncate.
3. **Отказ зависимостей: `create_service_collection` падает** → весь `run` мёртв.
   Защита: тот же путь, что и у тулов (`RuntimeCoordinator`), ошибка — явная.
4. **TOCTOU: скрипт читает `mtime:size`, пишет по устаревшему ack** → не применимо
   на read-only шаге (B); при C — блокер, токен обязан проверяться в момент записи.
5. **Конкурентность: два скрипта правят индекс одновременно** → гонка за SQLite.
   Защита: один писатель (read-only шаг пишет только в temp), либо сериализация.
6. **Сам протокол: «скрипт вместо тулов» превращается в «скрипт вместо проверки»**
   → агент возвращает свой же дистиллят и объявляет ✅. Защита: Guard в §11.1 —
   проверка = exit code/sha, а не текст скрипта.
