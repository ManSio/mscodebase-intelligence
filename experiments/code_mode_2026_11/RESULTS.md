# RESULTS — Code Mode: три руки, 48 замороженных запросов

**Статус: v2 (2026-11-15, вечер). Числа v1 отменены** — в v1 руке A подсказывали имя
gold-файла (`get_symbol_info(Path(gold).stem)`), и «потери» композита были частично
артефактом утечки. Файлы v1 лежат в `results/v1_superseded/`; ссылаться на них
нельзя. Причина отмены и оба blocker'а — в §0.

## 0. Что было не так в v1 (блокует старые выводы)

1. **Утечка в контроле.** Рука A получала `symbol = Path(gold).stem` — то есть имя
   ответа. В v2 символ для второго шага берётся **из ответа `search_code`**
   (первый путь в тексте), как это и делает агент. Итог: A 85.4% → **70.8%**.
2. **Отказы считались «потерей пути».** Из 11 «потерь» B в v1 пять были явными
   отказами (`ask_rewrite`/`abstain`), а не искажением. Механизмы разные → разные
   предписания протоколу, поэтому в v2 они считаются отдельными ведрами.
3. Плюс ниты ревью: `limit=10` у A против дефолта 8 у B (снято), `hit()` не понимал
   `./` и регистр (исправлено), «разброс ≤1%» был неверен (пересчитано), путь
   перевывода не работал без `tiktoken` (теперь явная ошибка).

## 1. Дизайн (не менялся)

| Рука | Механизм |
|---|---|
| **A** (control) | `search_code(quality)` → первый путь из ответа → `get_symbol_info` + `impact_analysis`; полные ответы |
| **C** (treatment) | **те же** ответы, спроецированные кодом: строки с путями/счётчиками/риском |
| **B** (альтернатива) | один композитный `investigate(query)` с дефолтами |

A и C видят один и тот же сырой ответ — сравнение контролируемое (разница только в
проекции). Модели в цикле нет: проекция написана вручную → замеряется **цена
контракта**, а не навык модели писать скрипт.

Входы заморожены до прогона: `frozen/HYPOTHESES.md`, `frozen/MANIFEST.json`
(sha256 `d4934cb7…d9fac`, 48 строк). Сырьё: `results/raw_texts/arm_texts.json.gz`,
метаданные — `results/run_meta.json` (git HEAD, статус индекса).

## 3. Проверка замороженных гипотез (пороги confirm/falsify — из HYPOTHESES.md)

| # | Гипотеза | Факт | Вердикт |
|---|---|---|---|
| H1 | C не теряет gold, который был в A | потеря 0 из 34 | ✅ CONFIRMED (тождество по построению) |
| H2 | медиана `tokens_C / tokens_A` ≤ 0.20 | **0.183** (−82%) | ✅ CONFIRMED |
| H3 | композит не отдаёт gold в ≥20% кейсов, где A отдал | 6 из 34 = **17.6%** (из них 3 отказа → 8.8% промахов) | ⚪ **INCONCLUSIVE** (мёртвая зона 5–20%) |
| H4 | `tokens_C ≤ 800` в каждом кейсе | >800 в 2/48, >1000 в 0/48, max 947 | ⚪ **INCONCLUSIVE** |

Парное сравнение (точный McNemar, те же 48 кейсов):

| Пара | A только | B только | несовпадающих | exact p |
|---|---:|---:|---:|---:|
| A vs B | 6 | 2 | 8 | **0.289** |
| A vs C | 0 | 0 | 0 | 1.0 (тождество) |

**Разница между цепочкой и композитом по попаданию в gold статистически не
показана** (p = 0.29). В v1 она «была» 11:0 — это и был артефакт подсказки.

## 4. Повторяемость

`compare_runs.py` по прогонам 1–3 (v1; в v2 менялся дизайн, поэтому склеивать
нельзя): 144 наблюдения, **0 переключений hit/miss**; расхождение размеров — A в 3

остановлен моим же ассертом скорера — доказательство, что контроль умеет падать.

## 5. Что это значит

1. **Выигрыш Code Mode здесь — в проекции, а не в выборе инструмента.** Один и тот
   же сырой ответ: 2 403 → 409.5 токенов (−82%) при **тождественном** попадании в
   gold (H1). Это не «проекция безопасна вообще»: фильтр держится на регэкспе путей,
   H1 не могла упасть на этом корпусе, и 14 кейсов, где gold не было у A, для C
   непроверяемы.
2. **Композитный тул — не замена и не проигрыш.** 62.5% против 70.8% при p = 0.29:
   разницы не показано. Но он в **17 раз медленнее** (3.84 с против 0.22 с) и в 3 из
   6 недопоставок честно отказывается (`ask_rewrite`) вместо ответа наугад.
   Прежний тезис «фузия теряет четверть точных путей» **снят** как артефакт.
3. **Слабое звено — не инструмент, а вывод символа.** Первый путь из ответа поиска
   совпал с gold лишь в **25 из 48** случаев. Цепочка A теряет попадания именно на
   этом шаге (символ берётся от чужого файла), а не на качестве поиска. Это довод в
   пользу кода: в скрипте шаг можно проверить (`if path != hit: continue`), в
   ручном цикле — нет.
4. **Бюджет ответа из одного замера не выводится.** max C = 947 в v2 против 1 572 в
   v1 при другом составе вызовов. Обещать «≤1 000» значит обещать число из одного
   прогона; правильнее правило «ответ — только поля, полный дамп — в файл + sha».
5. **Потолок recall задаёт корпус, а не механизм.** 14 из 48 кейсов не взяла ни одна
   рука; минимум один gold (`E30-E28-14` → `docs/en/HANDFOFF.md`) на диске
   отсутствует (файл лежит в `docs/archive/i18n/en/`). Атрибуция «из-за отключённых
   эмбеддингов» **не измерена** — абляции плотного канала в этом эксперименте нет.

## 6. Чего здесь нет

- Ходов модели и денег: модели в цикле не было. A = 1–3 хода, C = 1 ход — выведено из
  конструкции, не измерено.
- Содержания кода: C несёт пути и счётчики, но не тело функций; −82% относятся к шагу
  «где», а не ко всей задаче.
- Чувствительности к `limit`, к режиму поиска (`fast/quality`) и к плотному каналу.
- Контаминация: корпус e47 ранее использовался для настройки поиска — влияет на все
  руки одинаково, абсолютный recall оптимистичен. Два запроса делят один gold → 48
  наблюдений не независимы.
