# FROZEN — гипотезы и фальсификаторы (записаны ДО прогона)

Вопрос владельца (цитата): «система для агента... агент может перевести правильно
приблизительные названия функций или переменных... или я не правильно мыслю?»

Популяция: 12 вопросов на русском к двум английским репозиториям (9 — itsdangerous,
3 — iniconfig). Gold — файл, содержащий реализацию (проверено чтением исходников).

Плечи (одинаковый бюджет 3 хода на вопрос):
- **A (RU lexical):** 3 русские переформулировки, по одному поиску на ход.
- **B (EN lexical):** 3 английских перевода, сделанных СЛЕПЫМ суб-агентом; по одному
  поиску на ход.
- **C (RU dense):** 3 русские переформулировки, dense-поиск 768.

Метрика: `success@turn` — gold-файл попал в top-10 на ходе ≤k; ход = один поисковый вызов.

| # | Гипотеза | Фальсификатор | Почему может провалиться |
|---|---|---|---|
| H1 | Перевод агентом закрывает языковой разрыв: B достигает ≥9/12 уже на ходе 1 | <7/12 на ходе 1 | перевод даёт смысл, но не лексику кода (`sep`, `max_age`) |
| H2 | **Ожидаем провал:** RU-лексика без перевода даёт ≥9/12 на ходе 1 | <7/12 | английский корпус не содержит русских токенов |
| H3 | **Ожидаем провал:** dense(RU) лучше B на ≥2 кейсах уже на ходе 1 | разница ≤1 кейса | перевод уже закрывает класс, dense добавляет только шум |
| H4 | dense находит кейсы, где B провалился на ходе 1 (разрыв словаря) | таких кейсов 0 | нужны вопросы, где код не использует слова перевода |
| H5 | **Ожидаем провал:** три русские переформулировки доводят A до ≥9/12 | <7/12 | переформулировка по-русски не добавляет английских токенов |
| H6 | Контроль: positive находится, negative не даёт gold ни в одном плече | любой контроль падает | поломка харнесса/индекса |

Правило отчёта: `CONFIRMED` / `REFUTED` / `CANNOT VERIFY` по каждой строке, с сырым
выводом. H2, H3 и H5 записаны как ожидаемо провальные намеренно: если они пройдут,
это находка, а не норма.

## Pre-flight (зафиксировано до прогона)

- `dense_off=true` для A/B; `dense_off=false` и пересобранная таблица 768 для C.
- stale-таблица 384 удаляется ДО C; проверка: в логе нет `query dim(...) doesn't match`.
- Один процесс, тот же набор вопросов, тот же `limit=10`, без query expansion кода
  (expansion включён по умолчанию и одинаков для всех плеч — это часть продукта).
- Перевод и переформулировки сделаны вслепую: суб-агент не читал репозиторий и не
  знал gold; в запросах запрещено выдумывать идентификаторы.
- Механическая проверка утечки: ни один токен запроса не совпадает с именем символа
  gold-файла; отдельно фиксируется пересечение токенов запроса с текстом gold-файла.
