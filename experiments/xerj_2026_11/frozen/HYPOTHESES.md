# FROZEN — гипотезы и фальсификаторы (записаны ДО прогона)

> Обязательное правило §19.1: минимум **две** гипотезы, которые мы ожидаем **провалить**.
> Иначе это confirmation bias, а не эксперимент.

| # | Гипотеза | Фальсификатор | Почему может провалиться |
|---|---|---|---|
| H1 | `investigate` даёт выше correctness, чем grep, на 16 positive + 4 ambiguity задачах | correctness_B ≤ correctness_A | На задачах «где определено» grep по имени файла/символа почти идеален; выигрыш может быть только на «кто вызывает» и «что сломается» |
| H2 | `investigate` не выдумывает на 4 negative задачах | хотя бы один ложный `file:line` | Семантический канал на похожем запросе может вернуть «правдоподобный» файл |
| H3 | Наши `callers` дают P@10 ≥ 0.7 на трёх репо | P@10 < 0.7 хотя бы на одном | Наш граф строится из AST; динамические вызовы (`getattr`, декораторы, DI) он не видит |
| H4 | **Ожидаем провал:** `impact` покрывает ≥ 90% файлов, которые реально ломаются | < 90% | Impact строится по статическому графу; тесты и конфиги в него не входят |
| H5 | **Ожидаем провал:** наш freshness ловит «восстановленный из tar» файл без ложных срабатываний | ложное «свежо» **или** лавина переиндексации | stat-first + hash-confirm даёт ложные пропуски только при совпадении mtime и размера; проверить, что не наоборот |
| H6 | **Ожидаем провал:** дефолтный профиль ≤ 25 000 B схем | > 25 000 B | 17 тулов с подробными описаниями легко дают 30–40 KB |

Правило отчёта: по каждой гипотезе — `CONFIRMED` / `REFUTED` / `CANNOT VERIFY`, с сырым выводом.
H4–H6 записаны как ожидаемо провальные намеренно: если они пройдут — это находка, а не норма.
