# 4A — Unit of return + контуры против confound'ов агентной аппаратуры

**Статус:** 🟡 pre-registered (дизайн заморожен, прогона нет).
**Повод:** протокол Tom Jones `3fj0o` («four arms, everything else frozen», замок сверху — closed book) + вопрос владельца: **будет ли запуск чистых opencode-агентов/субагентов как-то влиять на эксперимент.**
**Короткий ответ:** ДА. В этом репо уже зафиксированы 6 каналов влияния (E7, E11, E17, E25, инцидент портов). Ниже — они и обязательные контуры. Дизайн без этих контуров повторяет ошибки, которые мы уже совершали.

---

## 0. Почему именно этот эксперимент

`3fj0o` — единственный протокол Tom, который меряет **не качество модели, а свойство системы** (что доходит до читателя). Он даёт число, которого у нас нет: **на каком документе останавливается top-1**. У Tom — 0/14. У нас — неизвестно, и это прямо проверяемо на нашем индексе. Плюс он проверяет его предсказание о **двух популяциях** (код vs проза) — у нас есть оба корпуса в одном репо (код + `docs/**`).

## 1. Плечи (заморожены)

| # | Что читателю | Роль |
|---|---|---|
| A | top-k чанков (текущий деплой) | baseline |
| B | top-1 целого документа (единица под тестом) | гипотеза |
| C | oracle-файл, нарезанный на чанки | потолок: ретрив или единица |
| D | **ничего** (closed book) | контроль, который никто не ставит |

**Заморозить ДО прогона:** ретривер, top-10, список запросов, судью, число прогонов (1/плечо на прогон), n на популяцию. Отличается **только** единица возврата.
**Популяции разделить ДО просмотра результатов:** `code` (чанки кода) и `prose` (корпус `docs/**`).
**Предказание (проверяемое):** проза — whole-doc на уровне closed book или ниже; код — нет. Если обе сдвинулись одинаково — двухпопуляционная история Tom на нашем индексе неверна, сообщаем независимо от исхода.
**Стоп-условие G6:** панель из 35 запросов мы уже видели → только свежий замороженный набор, иначе явная пометка `in-sample`.

## 4. Runbook: как запускать чистого агента, не портя результат

1. **Проверить живость:** `debug_runtime_passport()`; `netstat` на :8080/:8081 — чужой llm не должен занимать порты нашего прогона.
2. **Изоляция:** `MSCODEBASE_DATA_DIR=<tmp>` (индекс не трогаем); рабочие папки агентов — `%TEMP%/opencode/<exp>/`, MCP **off**, пустой корень.
3. **Шардинг:** генерация и суд — разные шарды; никакого общего контекста; opaque-токены вместо имён плеч.
4. **До прогона:** `verify_data` + decoy-audit + negative-control; записать манифест (модель, budget, n, seed).
5. **После:** убить все процессы агентов/llama; проверить, что индекс и БД не изменились; **не коммитить** артефакты с ПД/секретами; redaction на выходе (E9).
6. **Нельзя:** `git commit` в main без PR; удалять/пересобирать живой индекс; менять ретривер ради «лучшего» результата (это тюнинг под увиденное).

**Риск «всё испортить»** закрывается read-only + изолированный data-root + отсутствие MCP в шардах + запрет на commit. Индекс `.codebase_indices` не пишется — только чтение.

## 8. Review corrections (2026-09-26) — gates, обязательные

Внешнее ревью плана выявило 4 правки; приняты как жёсткие gate'ы (не советы):

1. **F0c → gate для F7 (публикация).** Ответ Tom / статья не начинается, пока F0c (~48 живых
   tracked-файлов с username) не закрыт **или** владелец явно не принял остаток с записанным
   обоснованием. Не «поймаем на финальном скане (F8)», а явный вход. Иначе утечка узнаётся постфактум.
2. **F3 (research) → gate для F5 (эксперимент).** Research-note обязан содержать раздел
   **«Design deltas»**: что из prior art совпадает с нашим дизайном (напр. Mem2ActBench), что
   заимствуем, чем отличаемся. F5 нельзя замораживать до применения дельт. Если наш 4-arm уже
   покрыт prior art — это **меняет дизайн/claim**, а не ложится в статью как контекст.
3. **Generalization set (held-out) — обязательный шаг.** Прошлый 5/5 arrival был **confirmation на
   известном провале** (мы уже знали: #16 = NONE 10/10), не тест на генерализацию. Нужен **свежий
   замороженный список симптомов, НЕ пересекающийся** с уже использованными и обсуждёнными (включая
   arrival-симптом «агент не пользуется высокоуровневыми тулами»). Список пишется ДО обращения к
   индексу, автором, который записей не читал. Метрика — контраст **held-out vs known** на одном
   индексе, а не «нашли ли Х». Иначе ответ Tom повторит уязвимость, которую мы у него же нашли.
4. **F6 Red Team: без процентов.** Каждая атака → статус `DEFENDED` | `OPEN (claim понижен)` |
   `FATAL (стоп)`. Любая `OPEN`, подрывающая claim, понижает вывод до «direction, not result».
   Правило «≥3 атаки, ≥2 с защитой» **убрано**: прошедшая без защиты атака — это дыра, а не
   допустимый процент прохождения gate.

## 9. F3 применён (design deltas) — gate F5 закрыт

Research-note: `RESEARCH.md`. Ключевое:
- **4-arm (closed-book / oracle / hard-negatives) — prior art** (Mem2ActBench, ACL 2026, arXiv:2601.19935).
  Новизну **убрать**; заявляем **репликацию на публичном code+prose корпусе** + наш plumbing-level
  partial-arrival (дифференциация самого Tom в `4745130`).
- **Judged-плечи: 10–20 trials majority + рандомизированный порядок + κ/flip-rate; t=0 — доп. мера (3–5 reps).**
  Обоснование: Coin Flip Judge (arXiv:2606.13685) — single-trial mean flip **13.6%** (~14/100), cross-judge **κ=0.51**;
  11 trials → ~5%; рекомендация авторов 10–20. «5 прогонов» невалидно.
- **Taxonomy** — Mem2ActBench (**5 типов**: Retrieval Miss / Retrieved-but-Unused / Hallucinated Default /
  Lossless Retention Failure / Tool Selection Error); два из них = наш EXP-24 и «hits and arrives partial».
  Отнесение нашего случая к plumbing-side — `[инференс агента]`, не факт статьи.
- **Hard negatives** = «most semantically similar», не random (Mem2ActBench).

F5 (4A run) замораживается только с этими дельтами.

## 10. Judge-confound — архитектурная контрмера (ОБЯЗАТЕЛЬНА)

Единственный из 6 каналов, у которого не было явной привязки к протоколу. Закрываем **архитектурно**
(не «постараться»):

- **Судья видит ТОЛЬКО output-bundle плеча** — ровно тот текст, который получил читатель. Не видит:
  метку плеча, gold, чужие плечи, собственные тесты/референс плеча.
- **Reference судьи — один и тот же объект для всех плеч.** (E17 v2: судья с тестами каждого плеча дал
  ложный эффект completeness p=0.0046; убрали конфаунд → p=1.00.)
- **Opaque arm-token + рандомизированный порядок.** Mapping `token→arm` хранится ВНЕ промпта судьи;
  seed — в manifest.
- **No self-grading.** Агент, произведший/получивший артефакт, не судит его (seat-модель Tom `4727138`).
- **Обязательный контроль утечки:** тот же артефакт подать судье под **двумя разными метками** → вердикт
  обязан совпасть. Не совпал → судья читает метку → прогон невалиден.

## 11. G6 — операциональное стоп-условие (проверяемое)

Набор «свежий» (допущен к F5) только если **до** любого обращения к индексу/каталогу:
1. Автор набора **не читал** каталог/записи (декларировано; при конфликте — независимый контекст/владелец).
2. `python scripts/frozen_overlap_check.py <new_list>` печатает **`OVERLAP: PASS`** — нет точных дублей и
   нет пункта, делящего ≥3 content-токена с любым ранее использованным (включая arrival-симптом).
   Negative control встроен (проверен на дубле → FAIL).
3. sha256 набора зафиксирован в freeze-таблице **до** прогона.
4. n на плечо и разделение популяций — заполнены.

Любое невыполнение → набор не «свежий», F5 не запускается.
