# F5 — judged reader arm: план и измеренный блокер

**Статус:** ⏸️ harness готов и проверен (dry-run + прямые вызовы), **полный прогон не выполнен** —
упирается в бюджет вызовов (см. ниже). Решение владельца требуется (§3 HALT / §5).

## Дизайн (по README §1, §10 judge-confound)

- Читатель получает контекст плеча (A top-k чанков / B top-1 целого док / C oracle gold / D пусто)
  + вопрос; отвечает 1–3 предложения.
- **Судья — другая модель** (no self-grading), видит ТОЛЬКО: вопрос + одинаковый reference
  (`evidence_span`) + ответ-кандидат под opaque-токеном; имя плеча не видит.
- Majority по `--trials`; `--judge-repeats` → flip-rate судьи; `--leak-check` (тот же артефакт под
  двумя метками → вердикт обязан совпасть).
- Итог: correctness по плечам × популяциям, `κ`/flip-rate.

## Реализация

`scripts/f5_judged_run.py` (opencode CLI; raw API-ключи не используются — §3).
Проверено: `--dry-run` (plumbing, 16 итераций), прямой `_run` возвращает `OK` + `longcat-2.0`.

## Измеренный блокер (числа, не «ожидается»)

| вызов | секунды |
|---|---|
| тривиальный (без `--file`) | **8.4** |
| реалистичный (контекст 7.4 KB + вопрос) | **~200** |

→ 1 запрос × 4 плеча (reader+judge) ≈ **~15 мин**; полный F5 (n=16 × trials 10–20) ≈ **часы–дни**
через CLI. Дизайн (10–20 trials majority) через opencode CLI **неисполним** в разумном бюджете.
