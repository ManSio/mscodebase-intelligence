## 1. В `AGENT_DIARY.md` — Post-Mortem

```markdown
## 2026-10-03 prompt-robustness-v3 — МЕТРИКА ШУМИТ ГРОМЧЕ СИГНАЛА

**Status.** Отрицательный результат закрыт. Ветка `exp/prompt-robustness-v3`,
коммиты `c24336a1..856ccf52`.

**Root Cause.** Один, и он не в коде матчера: инвариантность меряется строковым
матчером, а сам матчер ошибается чаще, чем ошибаются модели. Ручная разметка всех
17 строк, отклонённых матчером, дала 16 ложных отказов против 1 настоящей ошибки
модели из 360 вызовов. Сигнал `1/360 = 0.28%`, шум `16/360 = 4.44%`, отношение
**16 : 1**. Ловить событие частотой 0.28% требует прибора с ошибкой ниже 0.28%;
лучший реализованный строковый матчер — 4.44%.

**Второй, независимый вывод (дороже первого):** калибровать матчер по живым
ответам модели **невозможно принципиально**. Все 120 живых ответов фактически верны,
неверных нет, поэтому FP не измеряется — знаменатель пуст, и «FP = 0» получается
тривиально. Ошибки моделей сидят в непервых повторах, а правило отбора «первая
base + первая paraphrase» их исключает.

**Fix.** Не чинится настройкой. Целевая частота слишком мала для прибора этого класса.
Изменено: fail-closed контрольная рука (`CONTROL_OK/CONTROL_FAIL` + exit 1) вместо
`N/A`+0 — раньше контроль физически не мог сообщить о собственной слепоте;
`STRICT_PASS` / `CONDITIONAL_PASS` вместо одного `PASS`.

**Guard.** `experiments/prompt_robustness/calibrate_matcher.py` — гейт калибровки
падает на FN, на FP и на пустой выборке (exit 0/1/2), есть `--selftest`. При запуске
нового измерения устойчивости **сначала** посчитать шум/сигнал по сырым строкам
и проверить, есть ли в выборке хоть один неверный ответ; если нет — измерять нечего.

**Побочный дефект дизайна, не связанный с матчером.** Знаменатель
`invariance_given_base_correct` — функция самой модели (условие `if base_ok:
inv_den += 1`), поэтому n = 30/21/27/27/24/30, и при фиксированном пороге 0.90 гейт
требует 4 расхождения при n=30, но только 3 при n<=27. Колонку вердиктов нельзя
сравнивать между моделями. Условие отбирает ровно те строки, где модель была права,
то есть где стабильность легче всего, — поэтому чем модель слабее, тем лучше её
инвариант. Живой артефакт: longcat/en — худшая точность (0.7), лучший инвариант (1.0),
вердикт `STRICT_PASS`.
```

## 2. В `WISDOM.md` — по одному факту, без истории

```markdown
- Прибор шумит в 16 раз сильнее сигнала: строка-матчер ошибается в 4.44%, модели —
  в 0.28%. Метрика устойчивости на строковых правилах не измеряет устойчивость.
- Калибровать матчер по живым ответам модели нельзя: модели почти не ошибаются,
  поэтому FP не имеет знаменателя. Отрицательные примеры приходится выдумывать —
  и тогда калибруешься на своём воображении (v2: FP 0.212 на выдуманных отрицательных).
- `invariance_given_base_correct` имеет модель-зависимый знаменатель, поэтому вердикты
  разных моделей не сравнимы между собой. Условие по корректности хвалит слабых моделей.
- Правило `bare` (ответ = ровно одно значение) ловит одну форму из класса «значение +
  оформление»: `100°C (212°F)`, `1912 год.`, `Кислород (O₂)`, `cannot find` — все верны,
  все FN. 16 из 17 отказов принадлежат этому классу.
- Ошибки LLM в повторных прогонах живут в НЕпервых повторах. Отбор «первый ответ»
  систематически их исключает — и выборка получается стопроцентно верной.
```
