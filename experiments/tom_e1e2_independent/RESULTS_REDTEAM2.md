| акт | итог | разбор |

**Вывод:** матчер читает ровно текст команды. Всё, чего нет в тексте буквально
(декодированное, экранированное, обрезанное), — невидимо. Переменная окружения
не прячет (текст присваивания виден), всё остальное — да.

## Блок 2. Отравление seen — измерено до ключа леджера. Исправлено дважды.

Первая версия этого пункта была неверна дважды, и обе ошибки — наши:
1. Подделка леджера без ключа схемы `_ledger-schema: 2` — загрузчик сносит все
   счётчики сессий как «наследие», так что тест проверял пустой леджер.
2. Подделка без `session-last` — чистка стирает счётчики мёртвых сессий.

С правильной подделкой (схема + живая сессия + окно прошло):

| проверка | итог |
|---|---|
| `seen=3`, окно прошло | **пусто — cap срабатывает ровно** |
| `seen=2`, те же условия | выдача есть — cap различает точно на 3 |
| живые повторы 5 раз | **[1,0,0,0,0]** — душит бэкoff со второго, cap не достаёт |
| тривиальный акт, затем опасный через 30 с | опасный пуст; ключ бэкоффа `act:bash:<кристалл>` — тип акта |

То есть cap=3 существует и работает, но в живых повторах его опережает временной
бэкoff (3 мин × 2^n). «Выжженная земля» — буквально: после одного срабатывания
любой bash-акт в окне подавляется для этого кристалла.

## Блок 3. Fail-open — ответы на все три вопроса ТЗ

| поломка | итог |
|---|---|
| леджер — битый JSON | **возврат + выдача как ни в чём не бывало** (fail-open) |
| кристалл с битой шапкой | молча пропущен, остальные грузятся (fail-open) |
| ctx 10 МБ | 0.4 с, выдача есть — ReDoS нет, тормозов нет |

Главный вопрос ТЗ закрыт измерением: **движок fail-open**. Битое состояние лечится
забыванием (считает, что ничего не видел, и выдаёт заново), а не остановкой.
Для «забора» это решение в пользу доступности против безопасности — и оно нигде
не названо.

## Блок 4. TOCTOU

Измеримое: тело heredoc видимо, `&` не прячет. Архитектурное: проверка и выдача
синхронны внутри одного вызова — внутрипроцессной гонки нет; окно «файл поменялся
между проверкой и исполнением» неустранимо для pre-exec хука по построению.

## Блок 5. Масштаб — линейно и больно

| N | загрузка склада | один матчинг |
|---|---|---|
| 100 | 0.87 с | 0.034 с |
| 1000 | 8.02 с | 0.326 с |
| 5000 | 39.07 с | 1.735 с |

Обе кривые линейны (~8 мс/кристалл на загрузку, ~0.35 мс на матчинг).
При 5000 кристаллов матчинг одного акта — **1.7 с**, за порогом боли 300–500 мс (синтетика с 2 ключами на кристалл — для настоящих привязок будет хуже; порог ~500 мс проходится около ~1400 кристаллов при 0.35 мс/шт.)
из ТЗ. При таком N хук на каждый ввод будет лагать, и его отключат — ровно тот
исход, которого ТЗ боится.
