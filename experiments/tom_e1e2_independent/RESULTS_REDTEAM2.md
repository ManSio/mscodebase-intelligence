## Блок 1. Обход через обфускацию

| акт | итог | разбор |
|---|---|---|
| `CMD="cargo"; $CMD build` | СРАБОТАЛ | подстрока на месте — переменная не прячет |
| `VAR=cargo python script.py` | СРАБОТАЛ | то же |
| `echo Y2FyZ28K \| base64 -d \| sh` | ТИХО | **обход**: ключа про base64 нет |
| `c\argo --version` | ТИХО | **обход**: литерала `cargo` нет |
| ANSI `car ESC[31m go` | ТИХО | **обход**: литерала нет |
| heredoc с `eval` в теле | СРАБОТАЛ | тело сканируется |
| 2001+ мусора + `eval` | ТИХО | **обход обрезкой**: видно только первые 600 символов |
| `... \| tail -20 &` | СРАБОТАЛ | `&` не прячет |

Первые две строки моей серии были испорчены моим же текстом (внутри сидели `go build`
и `go test` — сработало по ним, а не по проверяемому). Переделано чистыми вариантами
с контролем (`cargo --version` срабатывает). Итог выше — после переделки.

**Вывод:** матчер читает ровно текст команды. Всё, чего нет в тексте буквально
(декодированное, экранированное, обрезанное), — невидимо. Переменная окружения
не прячет (текст присваивания виден), всё остальное — да.

## Блок 2. Отравление seen — сильнее, чем в ТЗ

| проверка | итог |
|---|---|
| один акт 5 раз в сессии | **[1,0,0,0,0]** — душится со второго, а не с четвёртого |
| тривиальный акт жжёт green-tests, опасный через 30 с | опасный пуст |
| ключ бэкоффа | `act:bash:<кристалл>` — **тип акта, не текст** |

Ожидалось `[1,1,1,0,0]` по cap=3. Измерено строже: душит бэкoff с трёхминутным окном
уже со второго повтора. Cap=3 не успевает сработать при повторах.

«Выжженная земля» подтверждена буквально: после тривиального срабатывания **любой**
bash-акт в окне подавляется для этого кристалла, каким бы релевантным ни был.
Ключ бэкоффа не различает тексты.

## Блок 3. Fail-open — ответы на все три вопроса ТЗ

| поломка | итог |
|---|---|
| леджер — битый JSON | **возврат + выдача как ни в чём не бывало** (fail-open) |
| кристалл с битой шапкой | молча пропущен, остальные грузятся (fail-open) |
| ctx 10 МБ | 0.4 с, выдача есть — ReDoS нет, тормозов нет |

Главный вопрос ТЗ закрыт измерением: **движок fail-open**. Битое состояние лечится
забыванием (считает, что ничего не видел, и выдаёт заново), а не остановкой.
Для «забора» это решение в пользу доступности против безопасности — и оно нигде
не названо.

## Блок 4. TOCTOU

Измеримое: тело heredoc видимо, `&` не прячет. Архитектурное: проверка и выдача
синхронны внутри одного вызова — внутрипроцессной гонки нет; окно «файл поменялся
между проверкой и исполнением» неустранимо для pre-exec хука по построению.

## Блок 5. Масштаб — линейно и больно

| N | загрузка склада | один матчинг |
|---|---|---|
| 100 | 0.87 с | 0.034 с |
| 1000 | 8.02 с | 0.326 с |
| 5000 | 39.07 с | 1.735 с |

Обе кривые линейны (~8 мс/кристалл на загрузку, ~0.35 мс на матчинг).
При 5000 кристаллов матчинг одного акта — **1.7 с**, за порогом боли 300–500 мс
из ТЗ. При таком N хук на каждый ввод будет лагать, и его отключат — ровно тот
исход, которого ТЗ боится.
