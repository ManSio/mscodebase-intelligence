## Вердикты

- **H1 — CONFIRMED.** RT ON ≈ 8.9–10.3 мс/файл, RT OFF ≈ 0.32 мс/файл.
  Множитель **28–32×**, одна сессия, тот же харнесс, свежие файлы с nonce.
  Наши записанные 8.68/8.02/7.81 мс/файл = в точности RT-ON класс.
- **H2 — CONFIRMED.** `candidates(repo=)` внутри снова зовёт `load_crystals`
  (`crystal_act.py:416`). Поэтому cand_repo (0.34–0.49 с) ≈ load_warm, а НЕ
  matching. Чистое совпадение при переданных `crystals=loaded` = **2.1–2.2 µs**
  на кристалл — совпадает с Томом (3 µs). Наши «0.35 ms/кристалл» были
  тёплой повторной загрузкой, а не совпадением.
- **H3 — REFUTED.** Один NVMe SSD, C и D — один физический диск. «Забытого
  диска» нет.
- **H4 — REFUTED.** Наша эссенция 1335 символов против ~1000 у Тома = 1.3×,
  не может дать 100–200×.
- **H5 — REFUTED.** Остаток ~8.7× (0.318 мс против 0.037 мс у Тома) = стоимость
  open на Windows на Python (open_head = 136 µs/файл при n=1000). Совпадение
  идентично (2.1 против 3 µs). Алгоритм ни при чём; INSTALL.md объявляет
  macOS/Linux, Windows untested.

## Контроли (харнесс обязан уметь падать и показывать ноль)

- Positive: RT-ON прогоны показали реальную стоимость (9–10 мс/файл) — харнесс
  ловит стоимость. `sleep(50ms)` → 50.3 мс.
- Negative: пустой склад → load 0.00041 с, 0 кристаллов; candidates пусто → 0.
- Обратимость: on → on → off → off, обе пары согласованы.

## Red Team (атака → защита)

1. «Это кэш страниц, а не AV» → обе руки: файлы только записаны (данные в
   кэше в обоих случаях). RT-ON warm (0.37–0.56) ≈ RT-OFF cold (0.32), но
   RT-ON cold = 9–10 с. Кэш страниц не даёт 9 с; это сканирование при доступе.
2. «AV кэширует вердикт по пути» → unique nonce на прогон, склад удаляется,
   результат воспроизводится.
3. «Таймер врёт» → perf_counter, sleep-контроль 50.3 мс, ноль-контроль 0.00041 с.
4. «candidates и правда делает работу» → чтение кода :416 + замер preloaded=2 µs.
5. Выброс on1 match=3.86 µs → шум, в вывод не берётся.

## Итог

Разрыв **объяснён на 100%**, алгоритм не при чём:
1. **~28–32× — Defender real-time** на первом открытии файла (у Тома — macOS/Linux).
2. **«matching» у нас был не matching**, а повторная загрузка; реальное совпадение
   2 µs ≈ Тома 3 µs. ⇒ наше число 0.35 ms/кристалл **отозвано**.
3. Остаток ~8.7× — Windows open-overhead, вне объявленной поддержки (§19.7).
