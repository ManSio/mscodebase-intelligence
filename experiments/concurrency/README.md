# Concurrency vs Semantic — гонки при замене примитива (§2.3)

**Проблема:** замена thread-safety механизма (lock → pool → queue) создаёт новую поверхность
для гонки; «0 errors» ≠ верные данные.

**Статус:** ✅ 2026-08-11 (исследование, стресс-тесты).

**Артефакты:**
- `experiment_concurrency_vs_semantic.py` — базовый сценарий.
- `experiment_concurrency_vs_semantic_attacks.py` — атаки: общий словарь результатов, общий
  correlation id, подмена результата между входами.

**Вывод:** тест обязан сверять, что вернувшийся результат принадлежит правильному входу
(не только отсутствие исключений). Правило: §2.3 AGENTS.md.
