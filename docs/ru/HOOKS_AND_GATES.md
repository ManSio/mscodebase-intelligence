# Хуки и гейты

> Перевод: 2026-11-08, источник — docs/en/HOOKS_AND_GATES.md. Английская версия — канон.

> Переписано 2026-11-08 по `.githooks/pre-commit`,
> `.opencode/plugin/mscodebase_gate.ts`, `scripts/*` и `.github/workflows/ci.yml`.
> Каждый гейт ниже прочитан в исходнике; тайминги замерены там, где это указано.

Коммит проходит через **три слоя**. Они намеренно перекрываются: плагин уровня хоста
ловит модель, git-хук ловит каждый коммит независимо от хоста, CI ловит то, что может
скрыть грязное рабочее дерево.

```
agent/host ──► .opencode/plugin/mscodebase_gate.ts   (per git commit, in-session)
git commit ──► .githooks/pre-commit                   (12 gates + gate-zero pytest)
push / PR  ──► .github/workflows/ci.yml               (6 jobs)
```

## 1. Плагин OpenCode (хук уровня хоста)

Файл: `.opencode/plugin/mscodebase_gate.ts`. Он срабатывает только для вызовов
инструмента `bash`, команда которых соответствует `git commit`.

| Гейт | Режим | Что делает |
|---|---|---|
| `stale_detector` | **block** (`MSCODEBASE_STALE_GATE=off` для отключения) | Сравнивает заявленные в документации версии с кодом; дрейф > 0 прерывает коммит |
| `graph_query isolation` | **advisory** (возможны `block`/`off`) | Считает узлы, которые осиротеют от коммита; текст дописывается к результату инструмента вместо блокировки |

Детали, важные для отладки:

- Он вызывает `python -m src.cli <tool> '<json>'` в каталоге проекта, то есть те же
  классы инструментов, что и MCP, но без протокола.
- Интерпретатор: `MSCODEBASE_PY`, по умолчанию `<repo>/venv/Scripts/python.exe`.
- Каждый вызов пишется как JSON-строки в
  `MSCODEBASE_GATE_LOG` (по умолчанию `%TEMP%/opencode/mscodebase_gate.log`).
- Любой сбой проглатывается и логируется; бросает только намеренная блокировка.
- Гейт изоляции стоит ~8 с на каждый `git commit` (замерено по логу), гейт дрейфа
  быстрый. Оба выполняются до git-хука, поэтому медленный первый гейт ощущает агент.
- С 2026-11-08 плагин пропускает гейт изоляции, когда все файлы в индексе —
  документация (`*.md`, `*.txt`, `*.rst`): документы не могут осиротить узлы графа, и
  это убирает ожидание на docs-only коммитах. Гейт дрейфа при этом работает — именно
  документацию он и проверяет. Проверено прогоном плагина на временном репозитории:
  `README.md` в индексе → `isolation_skipped`, `a.py` → `isolation`.
- Известное ограничение: пока процесс MCP держит блокировку БД, CLI ждёт её до 8 с, а
  затем отвечает `base: cached` с пустым списком изменённых файлов. Считайте этот
  advisory best-effort: git-хук и CI от него не зависят.

## 2. Git-хук pre-commit (репозиторий)

Активен, когда `git config core.hooksPath` = `.githooks` (этот репозиторий).
Устанавливается или проверяется инструментом `install_git_hooks`
(`action = install | uninstall | status`) либо ручной установкой `core.hooksPath`.

Бюджет на гейт: `MSCB_PRECOMMIT_GATE_TIMEOUT` (по умолчанию 900 с). Gate-zero (полный
`pytest tests/`) автоматически пропускается, когда в индексе только файлы
документации, и может быть пропущен через `MSCB_PRECOMMIT_FAST=1`.

| # | Команда | Блокирует на |
|---|---|---|
| 0 | `pytest tests/` | любом упавшем тесте (пропускается для коммитов только с документацией) |
| 1 | `scripts/verify_diary.py` | утверждениях `✅` в `AGENT_DIARY.md`, которые реестр противоречий не может подтвердить |
| 2 | `scripts/stale_detector.py --staged` | дрейфе версий между документами в индексе и `pyproject.toml` |
| 3 | `scripts/check_tool_names.py` | мёртвых именах `intel_*`/инструментов в документации |
| 4 | `scripts/negative_controls_runner.py` | зарегистрированном guard'е, который не может упасть |
| 5 | `scripts/check_layer_boundaries.py` | импорте `mcp`/`sources` из `core` вне переходного allowlist |
| 6 | `scripts/architecture_linter.py` | инвариантах архитектуры (реестр, циклы, устаревшие имена) |
| 7 | `scripts/lock_guard.py` | активных lock-файлах git (advisory) |
| 8 | `scripts/check_known_issues.py` | `KNOWN_ISSUES.md` длиннее 300 строк или отсутствующем месячном архиве |
| 9 | `scripts/check_third_party_data.py` | персональных данных / дословных чужих дампах в файлах индекса |
| 10 | `scripts/check_parallel_sessions.py` | файле в индексе, который редактирует другой worktree |
| 11 | `scripts/ruff_gate.py` | ошибках линтера в Python-файлах индекса |
| 12 | `scripts/gate_cli.py` (`tools/verification/gates.py`) | G1 population, G2 referent, G3 generalization, G4 control |

Два следствия, которые стоит помнить:

- Гейт, покрасневший из-за чужих незакоммиченных файлов другой сессии, всё равно
  красный гейт. Исправьте причину или коммитьте с явным, задокументированным
  `--no-verify`.
- Хук запускает `pytest` на каждом не-doc коммите; измерьте, прежде чем винить агента
  за трёхминутный коммит.

## 3. CI (`.github/workflows/ci.yml`)

| Job | Что доказывает |
|---|---|
| `test (ubuntu-latest, 3.14)` | полный набор с покрытием (`-n auto`) |
| `test (windows-latest, 3.14)` | проверенная платформа; ловит взаимные блокировки, только-Windows |
| `clean-state` | свежий клон + venv + установка по lock + полный набор; также гоняет negative controls |
| `manifest-parity` | наши извлекатели манифеста против закреплённого `osv-scanner` на корпусе-полигоне |
| `docker-build` | удалённый образ всё ещё собирается |
| `transport-equiv-e2e` | stdio и Streamable HTTP возвращают одинаковые ответы |

CodeQL запускается отдельно (`.github/workflows/codeql.yml`). Python 3.14 —
единственная поддерживаемая версия.

## 4. Зачем нужен каждый слой

- **Плагин** — ловит агента до того, как вернётся `git commit`, сообщением, которое
  модель может прочитать.
- **Git-хук** — ловит людей и любой хост; единственный слой, который по умолчанию
  прогоняет полный набор тестов.
- **CI** — ловит то, что зависит от чистого дерева: дрейф lock-файла, установки с
  чистого состояния, Docker, эквивалентность транспортов.

Не «исправляйте» красный гейт его отключением. Если правило неверно — меняйте правило
и тест, который его охраняет, в одном коммите.
