## 1. Поддерживаемые версии

| Версия | Поддерживается |
|---|---|
| 3.5.x | да — текущая линия (`pyproject.toml`) |
| < 3.5 | нет; сначала обновитесь, потом сообщайте |

Патчи получает только последняя 3.5.x. Это заявление политики, а не то, что
проверяет код. Нижняя граница runtime — Python 3.14
(`requires-python = ">=3.14"`); отчёт против более старого интерпретатора вне
области рассмотрения.

## 2. Модель угроз

Сервер работает как **stdio MCP-процесс с правами пользователя, который его
запустил** — обычно пользователя хоста, без разделения привилегий, без
контейнера, без seccomp, по умолчанию без сетевого слушателя. Это одно
предложение определяет всё ниже:

- Он может прочитать любой файл, который может прочитать пользователь, и
  записать любой файл, который может записать пользователь. Песочницы вокруг
  самого сервера нет.
- Он индексирует и читает **недоверенное содержимое**. `AGENTS.md` репозитория,
  `SKILL.md`, комментарии в исходниках или загруженная страница — это *данные*.
  Они никогда не являются полномочием. `src/core/trust_boundary.py` классифицирует
  корни как `TRUSTED`, `UNTRUSTED` или `UNKNOWN`; `MSCODEBASE_TRUSTED_ROOTS`
  (разделённые `;` или `,`) — это явный allowlist. Инструкции из корня
  `UNTRUSTED` не исполняются, а запуск скриптов / push / установка из него
  требуют явного подтверждения владельца (`docs/TRUST_BOUNDARY.md`).
- Реалистичная атака — **prompt injection через проиндексированное содержимое**,
  а не удалённый эксплойт. Защита — ограниченные инструменты, preview-before-write
  и одна опасная возможность, выключенная по умолчанию.

## 3. `execute_script` — поверхность RCE

`execute_script` **выключен по умолчанию**. Он регистрируется только при
`MSCODEBASE_EXECUTE_SCRIPT_ENABLED=true` и тогда становится 70-м инструментом,
считаемым отдельно от 69.

Что код реально делает (прочитайте это перед включением):

- `src/core/sandbox/executor.py` проверяет исходник **до** исполнения: allowlist
  модулей стандартной библиотеки (`ALLOWED_MODULES`), блокируемые строковые
  шаблоны (`os.system`, `subprocess`, `open(`, `eval(`, `__import__`,
  `sys.modules`, `win32`, ...) и блоки уровня AST для обфусцированных импортов.
- Исполнение — подпроцесс с минимальным окружением: `PATH=""`, без копии
  `os.environ` (так что секреты родителя никогда не доходят до потомка),
  `PYTHONPATH` указывает на корень проекта, таймаут по умолчанию 30 s, лимит
  stdout/stderr 1 MB.
- Существуют три режима: `strict` (по умолчанию), `permissive`, `off`.

Docstring модуля говорит прямо: **«NOT a security boundary for untrusted code.
Defense-in-depth for agent tools.»** Считайте включение выдачей произвольного
исполнения кода под вашей учётной записью. Заметьте, что `.env.example` и
сообщение в логе при старте описывают это как работу «без изоляции песочницы»;
исполнитель выше — то, что инструмент действительно вызывает, и честная сводка
такова: «подпроцесс с AST-валидацией, а не тюрьма».

## 4. Записи: preview, impact guard, receipt

- `WriteTool.execute` по умолчанию работает с `apply=False`: каждый
  rename/move/replace/insert/delete возвращает **preview**. Ничего не пишется,
  пока не передан `apply=True`.
- Тот же метод декорирован
  `@modification_guard(pagerank_min=0.05, blast_min=10, ack_ttl=600)`. Для
  несущего файла (высокий PageRank или blast radius >= 10 связей) гейт
  **запрещает** запись и возвращает HMAC `impact_token`, привязанный к текущим
  `mtime:size` файла.
- `ack_impact(file_path, impact_token)` открывает окно на 600 s. Токен
  аннулируется, если файл изменился, поэтому устаревшее подтверждение не может
  авторизовать запись против другого содержимого. Простой ack без токена
  отклоняется.
- Неоднозначность отклоняется, а не разрешается: голый символ, совпадающий более
  чем с одним определением, возвращает `denied` со списком кандидатов вместо
  молчаливого выбора первого.
- Fail-closed: если поиск PageRank или blast radius падает, гейт считает файл
  горячим (PageRank 1.0 / blast 100) и требует ack.
- Каждая запись фиксируется через `ActionReceipt`; `get_action_receipt` (полный
  профиль) возвращает то, что было изменено.

## 5. Пути, чтения и индекс

- `SecurityConfig` разбирает `MAX_FILE_SIZE_MB` (10), `ALLOWED_EXTENSIONS`,
  `ALLOW_SYMLINKS` (`true`) и `STRICT_PATH_VALIDATION` (`true`) из окружения, но
  **никакой другой модуль сегодня эти четыре значения не читает**. Реальная
  фильтрация файлов живёт в `src/core/indexing/file_guard.py` (константа лимита
  размера, allowlist расширений, обнаружение минифицированных/бинарных файлов,
  шаблоны `.gitignore`), а реальное удержание пути — это явные проверки
  `is_relative_to` ниже. Не считайте env-флаги действующими средствами защиты.
- Удержание пути применяется там, где это важно, через `Path.resolve()` +
  `is_relative_to`: `read_live_file` при `MSCODEBASE_RESTRICTED_READ=true`
  (по умолчанию выключено — абсолютный путь вне проекта читается), `grep_code`
  (должен оставаться внутри корня проекта), каталог назначения загрузки и
  `autonomous_fix`.
- Самоиндексация запрещена: `resolve_indexer_for_request()` отклоняет каталог
  расширения и путь установки MCP вместо того, чтобы тихо индексировать свой
  собственный код.
- Индексатор пропускает `.git`, системные каталоги, бинарные файлы,
  минифицированные файлы, слишком большие файлы, пути из `.gitignore` и
  `experiments/**` (`file_guard.py`).
- Сервер не открывает TCP-порт, если вы не настроили транспорт
  (`MCP_HOST`/`MCP_PORT`, по умолчанию `127.0.0.1:8765` для SSE-моста). По
  умолчанию в сеть ничего не выставлено; эндпоинты llama.cpp/ONNX/LM Studio тоже
  loopback.

## 6. Секреты

- Секреты живут только в `.env`. `.env`, `.env.local`, `.mscodebase/`,
  `.codebase_models/` и `models/` в git-ignore.
- Ключ LM Studio по умолчанию `sk-local` в `.env.example` — документированная
  заглушка, а не учётные данные.
- Никогда не вставляйте ключ в аргумент инструмента, документ, тестовую фикстуру
  или строку лога. `src/core/redact.py` вырезает формы учётных данных с префиксом
  до того, как текст попадает в контекст агента, и его собственный docstring
  говорит, что это **не** граница безопасности — он ловит только известные формы.

## 7. Этот репозиторий публичный

Лицензия MIT и публичное чтение. Поэтому:

- Никаких выгрузок третьих сторон: спарсенных страниц, экспортов профилей, чужих
  email, целых статей. Здесь место нашему собственному выводу плюс `sha256`, URL
  источника и короткой цитате.
- Дословная копия заодно притаскивает лицензию источника (статья CC BY-NC-SA
  заразила бы репозиторий под MIT).
- Гейт: `scripts/check_third_party_data.py` работает в pre-commit. R1 (личный
  email) и R2 (подпись спарсенного профиля) блокируют; R3 (объёмный дословный
  чужой текст) — advisory; R4 ловит дампы тредов.
- Сырьё, которое нужно сохранить, живёт **вне** репозитория, в
  `<data_root>/audit-cache/<task>/`.

3. Не открывайте сначала публичный issue и не включайте в отчёт секреты или
   персональные данные третьих сторон.

Ожидайте первичный ответ в течение нескольких дней. Поскольку проект ведёт один
мейнтейнер, исправление может выйти как обычный патч-релиз, а не как бэкпорт.
